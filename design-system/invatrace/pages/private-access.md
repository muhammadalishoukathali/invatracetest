# Private access — page guidance

Extends `../README.md`.

**Routes:** `/private-access`, `/private-access/restore`,
`/private-access/recovery`, `/access`

**Mode:** Operate. The visitor must establish, safeguard, restore, or manage a
pseudonymous field identity without mistaking the flow for account signup.

## Composition

- The landing page pairs a factual privacy promise with a connected three-step
  access trail. The two actions remain adjacent and unmistakable.
- Recovery information is the visual focal point: public ID separated from the
  secret code batch, mono type only for the identifier and codes, and actions
  immediately below the batch.
- Restore is a narrow focused form. Access management lives in the authenticated
  app shell as divided equipment-ledger sections rather than dashboard cards.
- Mobile is the primary field layout. Desktop may split explanation from action
  but never changes the task order.

## Language and state

- Say “Private access,” “public profile ID,” “recovery code,” and
  “installation.” Do not say account, sign up, username, password, or login.
- State explicitly that profile IDs are public and recovery codes are secret.
- All restore credential failures use the same recovery-oriented message.
- Offline first run explains the one-time connection requirement; it never
  creates a provisional profile.
- Code rotation and non-current installation revocation require visible inline
  confirmation. Current-installation revocation is unavailable.
