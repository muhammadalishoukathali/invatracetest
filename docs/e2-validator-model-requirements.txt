INVATRACE ITERATION 1 — E2 SERVER VALIDATOR MODEL HANDOFF
Version: automated-v1.0

Purpose
-------
This model bundle is the independent server-side evidence validator used before
a volunteer report can appear on the public map. It is not the browser E1 model
and it must run without any external inference API. Until this bundle exists,
production reports correctly remain private with status validation_unavailable.

Required artifact
-----------------
Supply a versioned, checksum-addressed ONNX bundle that runs on CPU with
onnxruntime. A single multi-head model is preferred, but separate ONNX models
are acceptable when they share one documented preprocessing pipeline.

Required image input
--------------------
- JPEG bytes decoded with EXIF orientation applied.
- Manifest-declared colour space, resize/crop, interpolation, tensor layout,
  dtype, scale, mean, and standard deviation.
- A fixed supported input shape, preferably float32 [1, 3, 384, 384].
- Minimum image dimensions and behaviour for corrupt or truncated images.

Required outputs
----------------
1. plant_probability: calibrated probability that a usable plant subject is
   present.
2. quality_probability and quality_reason scores for at least blur, exposure,
   occlusion, and insufficient subject coverage.
3. spoof_probability: calibrated probability of replay/fake evidence,
   including a screen photo, printed photo, edited composite, or non-camera
   image where detectable.
4. ood_probability: calibrated probability that the image is outside the
   supported plant/image distribution.
5. species_logits: raw logits in exactly the 31-class order in
   PULIH_Model1_v4_FP16_Web_Kit/model/species_31.json. If a different taxonomy
   is necessary, provide a reviewed deterministic mapping and retrain the
   validation calibration against it.
6. embedding: a stable L2-normalizable float vector for same-plant duplicate
   matching across different photos.
7. model_version: immutable semantic version or artifact digest.

Required calibration and evaluation
-----------------------------------
- Independent Malaysian field-phone validation set, separated by location,
  contributor, and plant instance from training data.
- Per-output threshold tables and confidence intervals.
- Species top-1 accuracy and per-class recall/precision.
- Known-vs-OOD AUROC/AUPRC and false-accept rate at the proposed operating point.
- Spoof AUROC/AUPRC plus false-positive rate on genuine field photos.
- Quality-gate recall and false-reject rate by failure reason.
- Same-plant verification ROC, precision/recall, and threshold evaluation using
  positive photo pairs of the same physical plant and hard negatives of nearby
  plants of the same species.
- Breakdown by device, lighting, habitat, image resolution, and supported
  species. Include failure examples and known limitations.
- No data leakage from PULIH training/validation or threshold-selection sets.

Required bundle files
---------------------
- one or more *.onnx model files
- manifest.json with input/output names, tensor shapes, preprocessing,
  thresholds, taxonomy checksum, model version, and SHA-256 for every file
- model-card.md with training data provenance, licences, consent/privacy
  handling, intended use, limitations, and evaluation results
- calibration.json containing the exact production thresholds
- 10 or more non-sensitive golden test images or precomputed input tensors with
  expected outputs and tolerances
- LICENCE files for model, code, and training data as applicable

Acceptance requirements
-----------------------
- CPU inference succeeds in a Python 3.12 Linux container with no network.
- Golden tests are deterministic within declared numerical tolerances.
- Corrupt, oversized, empty, and non-image inputs fail safely.
- Every output is finite and within its declared range.
- The model cannot silently change the 31-class order.
- Model unavailability or timeout never publishes a report.
- Trust level may adjust only the soft identification-confidence threshold; it
  never bypasses spoof, OOD, quality, replay, or mismatch checks.

Current server policy consuming these outputs
--------------------------------------------
- Exact byte/capture replay: rejected.
- spoof_probability >= 0.80: rejected.
- Failed quality, no plant, ood_probability >= 0.50, GPS accuracy over 100 m,
  uncertain server ID, client/server species mismatch, or insufficient server
  confidence: needs_rescan.
- Independent valid target plus same-plant spatial/embedding match: merged.
- Independent valid target with no duplicate: confirmed and published.

The thresholds above are versioned application policy, not a claim about an
unsupplied model. Calibration evidence may justify a new policy version; do not
change them silently inside model code.
